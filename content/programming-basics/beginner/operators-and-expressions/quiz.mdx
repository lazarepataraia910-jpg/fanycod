შეამოწმე, რა დაგამახსოვრდა ოპერატორებსა და გამოსახულებებზე. თითო კითხვას ერთი სწორი პასუხი აქვს. გასავლელად საჭიროა 70%.

<Quiz>
### რას უდრის `4 + 2 * 5`?
- [ ] 30
- [x] 14
- [ ] 11
> ჯერ გამრავლება: 2 * 5 არის 10. მერე 4 + 10.

### რომელი ჩანაწერი ითვლის ორი რიცხვის საშუალოს სწორად?
- [ ] a + b / 2
- [x] (a + b) / 2
- [ ] a + (b / 2)
> ფრჩხილების გარეშე ჯერ გაყოფა სრულდება. ჯერ უნდა შეიკრიბოს, მერე გაიყოს.

### რა იქნება `x`-ში? `let x = 4; x *= 3; x -= 2;`
- [ ] 6
- [x] 10
- [ ] 12
> 4 * 3 არის 12, მერე 12 - 2 არის 10.

### რას აკეთებს `count++`?
- [x] count-ს ერთით ზრდის
- [ ] count-ს ორჯერ ზრდის
- [ ] count-ს ადარებს ერთს
> `++` იგივეა, რაც `count = count + 1`.

### რას დაბეჭდავს `console.log(8 !== 8);`?
- [ ] true
- [x] false
- [ ] 8
> `!==` ნიშნავს „არ არის ტოლი“. 8 ტოლია 8-ის, ამიტომ პასუხია false.

### რატომ ვიყენებთ `===`-ს და არა `==`-ს?
- [ ] `===` უფრო სწრაფად იწერება
- [x] `===` ტიპსაც ადარებს და მოულოდნელ პასუხს არ იძლევა
- [ ] `==` JavaScript-ში საერთოდ არ არსებობს
> რბილი `==` შედარებამდე ტიპებს ურევს, მაგალითად `0 == ""` true-ა.

### რას უდრის `true && !false`?
- [x] true
- [ ] false
- [ ] შეცდომას
> `!false` არის true, ხოლო `true && true` არის true.

### რომელი ამოწმებს სწორად, არის თუ არა `n` 1-დან 10-მდე?
- [ ] 1 <= n <= 10
- [x] n >= 1 && n <= 10
- [ ] n >= 1 || n <= 10
> ორივე პირობა ერთად უნდა სრულდებოდეს, ამიტომ `&&`. `||` თითქმის ყველა რიცხვისთვის true იქნებოდა.

### რას დაბეჭდავს `console.log("3" + 4);`?
- [ ] 7
- [x] 34
- [ ] NaN
> ერთი მხარე ტექსტია, ამიტომ `+` აერთებს.

### რას უდრის `Number("სამი")`?
- [ ] 3
- [ ] "სამი"
- [x] NaN
> სიტყვა რიცხვად ვერ იქცევა, ამიტომ შედეგია NaN, „რიცხვი არ არის“.
